# Join the MCP game from the browser

- **What:** the user plays a seat in the game an outside AI plays over MCP (`testing/mcp-player`): one live game the browser and the MCP server share.
- **Why:** The user (2026-09-26) wants to play in that game too; 2026-10-14: "I'd like to be able to play against haiku too".
- **Done when:** The user and an MCP player play one game together, each on their own seat.
- **Who:** Claude built it; the user plays it.
- **2026-10-14, built:** the game is one file both ends read and write (`.cache/mcp/table.json`, `view/shared-table.ts`); the dev server serves it at `/mcp/table` (`scripts/mcp/vite-plugin.ts`, refusing a write older than the file). `new_game` takes `human: <faction>`: the human is player 1, AI opponents default to none. `?join` plays that seat: orders and battles as in any game, the table written after every change, the other player's changes picked up by polling. The MCP player gets `wait` for the human's move. In a battle between the two, each gives their own side's orders, unit by unit (the browser replays the MCP player's from the table, animated); the MCP player's tarot hands there are the AI's picks, made alike at both ends. Whoever's map turn it is writes a finished battle back; the AI turns after the human's run in the browser, those after the MCP player's in the server. The `join` playtest fakes the MCP player in Node and fights a battle across the table. On the way, a crash fixed in the battle scene: its ground was copied before its image had loaded (three's `Texture.copy` flags the copy for upload at once), which a battle opened right after page load hit.
- **Try it:** `pnpm dev --host`; then `claude --model haiku --mcp-config scripts/mcp/disc.mcp.json --strict-mcp-config` from the repo root and ask it to start a game of disc against you (`human` with your faction); open `/?join`.
