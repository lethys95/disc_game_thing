# An outside AI plays over MCP

- **What:** a local stdio MCP server in `scripts/mcp/` running a headless game (the rules are pure, like `sim:world`); the other seats are the map AI. The real work: a compact, readable state description, and a list of what a player can do now on the map (the rules only answer "why not"). Dev tooling, kept out of `src/`. Joining that game from the browser is its own card (`eventually/mcp-join`).
- **Why:** The user (2026-09-26): "for shits and giggles". Asked for again 2026-10-14: "so AI such as yourself, a language model, can possess a player and make decisions. I'm thinking something cheap like a haiku model could do".
- **Done when:** An AI can play a whole game over MCP, and the user has seen it play.
- **Who:** Claude.
- **2026-10-14, built:** `pnpm mcp` (the server; `scripts/mcp/disc.mcp.json` points Claude Code at it) and `pnpm play` (the same tools on the command line). Tools: `new_game`, `look`, `act` (a numbered option and the listing's revision), `order` (a raw map action), `describe`. Every reply ends with numbered options: map orders checked by the rules' own `*Problem` functions, attack forecasts (WIN/LOSS), battle orders with a preview of each. The seat plays its own battles (or `battles: "auto"`); fog and battle secrecy as in the browser. The server's instructions are a rules primer (`primer.ts`). `?watch` in the browser follows the game save by save (`shots/mcp/game.json`), taking no orders.
- **2026-10-14, Haiku's playtest:** a Haiku agent played seven turns through `pnpm play` (the same text), took a city and a dungeon, won both its battles. Its notes led to: a fallen leader's line saying what that means, battle results naming who was lost, a line when the others have moved unseen. Its game ended on its own typo (the table and the watched save pointed at one file); the tools now refuse that.
- **Try it:** `claude --model haiku --mcp-config scripts/mcp/disc.mcp.json --strict-mcp-config` from the repo root, then ask it to start a game of disc and win it; watch at `/?watch` on the dev server.
